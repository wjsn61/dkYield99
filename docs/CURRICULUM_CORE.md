# dkYield99% 교육과정의 핵심

> # Python을 배우면서,
> # 데이터를 스스로 만들고
> # 그 숫자를 직접 계산해 의심할 줄 아는 엔지니어가 된다.
>
> **AI 시대에 대체되지 않는 엔지니어는, 그런 사람입니다.**

이 과목은 **Python 과목입니다.** 변수·조건문·반복문·함수를 처음부터 배웁니다.
다만 그 문법을 교과서 예제가 아니라 **학생이 직접 만든 공정 데이터** 위에서 배웁니다.

그래서 학기가 끝났을 때 남는 것이 문법이 아닙니다.
`for`문을 배운 사람은 많지만, `for`문으로 **자기가 만든 배치 데이터의 표준편차를 구해 보고
엑셀 값과 맞춰 본 사람**은 드뭅니다. 그 드문 쪽에 서게 하는 것이 이 과목의 목적입니다.

> ### 실무 + 코딩 + 분석 + DATA
>
> AI가 코드를 대신 써 주는 시대에, 엔지니어에게 남는 일이 이 넷입니다.
> 넷 중 하나만 빠져도 나머지가 무너집니다.

---

## 이 수업이 제시하는 방향

### AI 환각을 이기는 힘

AI는 **모르는 것을 모른다고 말하지 않습니다.**
그럴듯한 숫자와 그럴듯한 코드를, 아주 자신 있게 내놓습니다.
이것을 **환각(hallucination)** 이라고 부릅니다.

환각을 이기는 방법은 하나뿐입니다.

> ## 데이터를 스스로 구축하고,
> ## 통계를 코딩으로 직접 내보는 것.

읽는 것만으로는 안 됩니다. **만들어 봐야 압니다.**

| 단계 | 하는 일 | 왜 |
|---|---|---|
| **① 데이터를 구축한다** | 시드를 정하고, 조건을 바꿔 가며 여러 판을 돌리고, 라벨을 붙여 저장한다 | 내가 무엇을 어떻게 측정했는지 아는 사람만 그 데이터를 믿을 수 있다 |
| **② 코딩으로 통계를 낸다** | `for`문으로 합계를 구하고, 제곱합을 n-1로 나누고, 제곱근을 씌운다 | 한 번 만들어 본 사람만 `=STDEV.S()` 가 무엇을 하는지 안다 |
| **③ AI와 맞춘다** | 같은 계산을 AI에게 시켜 보고 내 코드의 답과 비교한다. 다르면 어느 쪽이 틀렸는지 찾는다 | 검산할 수 없는 답은 쓸 수 없다 |

| | |
|---|---|
| 대체되는 사람 | AI에게 시키고, 나온 답을 그대로 옮긴다 |
| **대체 불가능한 엔지니어** | **데이터를 직접 만들고, 코드로 계산해 보고**, AI의 답을 검산한다 |

### dkYield99%는 도구입니다, 목적이 아닙니다

dkYield99%는 **분석할 데이터를 만들어 내는 장치**입니다.
게임을 잘하는 것이 목표가 아니라, 게임이 뱉어낸 CSV를 가지고
**무엇을 말할 수 있는지**가 목표입니다.

게임의 「📊 통계 지표 보기」 화면도 정답표가 아닙니다.
**내가 코딩한 결과를 맞춰 볼 참고표**이고,
학생이 직접 만든 도수분포표·평균·표준편차가 맞았는지 확인하는 창일 뿐입니다.

### Python은 출발점이지, 도착점이 아닙니다

**화학공학을 아는 사람도, Python을 아는 사람도 많습니다.**
그러나 공정 데이터를 스스로 만들고, 코드로 분석하고, AI의 답을 검산하고,
그 판단에 책임질 수 있는 엔지니어는 드뭅니다.
드문 자리가 대체되지 않는 자리이며, 이 수업은 그리로 가는 **하나의 방향**을 제시합니다.

---

## 왜 이 넷인가

AI에게 "파이썬으로 관리도 그려 줘"라고 하면 3초 만에 나옵니다.
그러면 우리는 무엇을 배워야 할까요?

AI가 **못 하는 것**을 배워야 합니다.

| 기둥 | 사람이 하는 일 | AI가 못 하는 이유 |
|---|---|---|
| **DATA** | 공정 데이터를 **만들고 · 재고 · 의심한다** | AI는 없는 데이터를 만들어 내지 못합니다. 무엇을 어떤 계기로 잴지 정하는 건 엔지니어입니다 |
| **코딩** | AI에게 **무엇을 시킬지 정하고, 받은 코드를 읽는다** | 읽지 못하는 코드는 현장에 못 넣습니다. 틀린 걸 알아채려면 알아야 합니다 |
| **분석** | 나온 숫자가 **맞는지 판단한다** | AI는 그럴듯한 Cpk를 자신 있게 틀립니다. 검증은 사람 몫입니다 |
| **실무** | 그 판단을 **현장의 언어와 책임으로 옮긴다** | 설비를 세울지 말지 결정하고 책임지는 것은 사람입니다 |

스마트팩토리도, 디지털 트윈도, 공정 최적화 AI도 -
**데이터가 없으면 한 줄도 못 만듭니다.**

```
 "순도가 떨어진 건가,    12개월을 운전하고     CSV를 읽고          관리도·Cpk로        정비를 할지 말지

        ↑                                                                                  │
        └─────────────────────────  다음 질문이 생긴다  ←────────────────────────────────┘
```

> ### 어디를 팔지 정하고, 파내고, 정제해야 합니다.

## 기둥별 상세

### 🛢 DATA - 만들고, 재고, 의심한다

- **만든다** - 12개월을 운전하면 매 턴 30여 개의 공정값이 기록됩니다.
  순도는 **한 번이 아니라 5개씩** 뽑습니다. 한 번만 재면
  "값이 튄 건지 공정이 변한 건지" 알 수 없기 때문입니다.
- **잰다** - 우리는 진짜 순도를 **절대 알 수 없습니다.**
  온라인 GC가 알려주는 값(반복성 ±0.3%p)만 볼 수 있을 뿐입니다.
  **분석기를 설치하면 순도가 오르는 게 아니라, 순도를 더 정확히 알게 되는 것입니다.**
- **의심한다** - 시드 없는 결과는 아무도 재현할 수 없습니다.
  DOE에서 네 조건을 **같은 시드로** 돌려야 조업 변동이 같아지고,
  그래야 차이가 온도·환류비 때문이라고 말할 수 있습니다.

### 💻 코딩 - 시킬 줄 알고, 읽을 줄 안다

- 9~10주는 **외부 라이브러리 없이** 평균·표준편차·Cpk를 직접 만듭니다.
- 11주 엑셀 → 12주 pandas. **엑셀로 3분 걸린 걸 코드로 3초에, 그리고 파일 20개에 한꺼번에.**
- **AI 활용 과제**: 매주 "AI에게 이 계산 코드를 물어보고,
  나온 답이 내가 직접 만든 함수의 결과와 같은지 확인하라."
  AI는 답을 주는 도구가 아니라 **검산 대상**입니다.

### 📊 분석 - 맞는지 판단한다

이 과목의 큰 생각: **평균이 아니라 산포가 품질이다.**

> **🤖 매 통계 주차의 고정 과제 - AI 검산**
>
> 그 주에 배운 계산을 **AI에게도 시켜 보고, 내 결과와 맞춰 봅니다.**
> 맞으면 왜 맞는지, 다르면 어느 쪽이 틀렸는지 한 줄로 적습니다.
>
> AI가 틀리는 것은 실패가 아니라 **이 수업의 핵심 장면**입니다.
> 틀린 걸 알아챈 순간, 여러분은 이미 대체 불가능한 쪽에 서 있습니다.


일부러 걸려 보게 만든 함정들:

| 함정 | 어디서 만나나 |
|---|---|
| **교란변수** - 함께 움직이지만 원인이 아닌 지표 6개 | 14주. `환류비`가 높은 판일수록 `순도`도 높아 보입니다. 같은 카드가 둘 다 올렸을 뿐, 환류비만 바꿔서는 순도가 안 변합니다 |
| **측정오차 vs 공정변동** | 순도 0.3%p 하락 - 공정이 나빠진 걸까요, 분석기가 튄 걸까요? 측정 σ가 0.30이면 그 정도는 1σ 안쪽입니다 |
| **평균만 보는 함정** | "평균 98.2%인데 왜 반품이 나오나?" → 규격이탈률은 σ가 결정합니다 |
| **오차 전파** | 수율은 세 값의 **곱**입니다. 세 요소의 흔들림이 어떻게 합쳐지는지 손으로 계산해 실측과 맞춰 봅니다 |
| **OFAT의 비효율** | 온도와 환류비를 하나씩 바꾸면 교호작용을 영원히 못 봅니다 |
| **p값 오독** | "p값 = 가설이 틀릴 확률"은 틀린 해석입니다. 미국통계학회가 2016년 공식 성명으로 경고했습니다 |

> 매주 제출하는 분석노트에는 **"한계"** 칸이 있습니다. **비어 있으면 감점입니다.**

## 캡스톤 - 네 기둥이 한 번에

> ### "수율 99%에 도전하라 - 공정능력 리포트"

**게임을 잘 하면 A가 아닙니다. 왜 그렇게 됐는지 통계로 증명하면 A입니다.**

| 배점 | 항목 | 기둥 |
|---|---|---|
| 15 | 진단 - 기술통계 + 관리도로 **안정/불안정 판정** | 분석 |
| 20 | 운전 전략 - 카드 8~10종(연구 1장↑), 수율 곱셈 구조 근거 | 코딩·실무 |
| 20 | **DOE** - 2²↑ 요인설계를 같은 시드로, 주효과·교호작용 | DATA |
| 20 | **공정능력** - 개선 전후 Cp·Cpk, 측정오차와 공정변동 분리 | 분석 |
| 15 | **결론의 정직성** - 개선 안 된 항목 보고, 한계 2개 이상 | 실무 |
| 10 | **재현성** - 시드·코드·CSV 제출, 재실행 시 동일 결과 | DATA |
| -10 | Cpk 없이 "순도 평균이 올랐으므로 품질 개선" 주장 | |
| -10 | OFAT(한 번에 하나씩)만으로 최적점 주장 | |
| +5 | **관리도 이탈점의 원인을 게임 로그에서 특정** | |

**발표 필수 3요소** - 하나라도 없으면 발표 점수 상한 70%:
1. "내 데이터는 어떻게 만들어졌는가" (시드·부분군 크기·측정오차)
2. 분포 그림 1장
3. 불확실성 문장 1개

## 평가 비중

| 항목 | 비중 |
|---|---|
| 주간 코드·카드 실습 | 25% |
| 중간 공정팩 + **데이터셋 설명서** | 15% |
| **반복실험·데이터 분석 포트폴리오 (9~14주)** | 20% |
| 최종 검증 보고서 | 30% |
| 발표·토론 | 10% |

**추가 규정** - 재현 불가 제출물(시드·CSV 미첨부)은 해당 과제 최대 70%.
통계 교육에서 재현성은 성실성 문제가 아니라 **학습 목표 자체**입니다.

## 이 과목을 마치면

1. **데이터가 없으면 AI도 소용없다**는 것을, 공정 데이터를 직접 만들어 보며 안다.
2. AI가 준 코드를 **읽고 검산할 수 있다.**
3. 평균만 보고 판정하지 않고, **산포와 규격을 함께 본다.**
4. **측정오차와 공정변동을 분리**할 줄 알고, 함께 움직인 것을 원인으로 착각하지 않는다.
5. 인자를 **하나씩이 아니라 설계해서** 바꾼다.
6. 자기 결론의 **한계를 스스로 밝힐 수 있다.**

> 이 여섯 가지가 AI 시대 공정 엔지니어의 최소 요건입니다.
